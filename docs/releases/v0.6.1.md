# OpenCode Pool Gateway v0.6.1

## 版本概览

本补丁版本修复第三方客户端和 OpenCode 上游之间的鉴权头兼容问题。客户端现在可以使用 Bearer 或 `x-api-key` 调用本站，网关会根据目标协议自动转换为 OpenCode 所需的鉴权格式。

## 客户端鉴权

以下两种方式均可使用令牌管理页面创建的本站访问令牌。

Bearer：

```http
Authorization: Bearer gq_your_gateway_token
```

API Key：

```http
x-api-key: gq_your_gateway_token
```

## 上游鉴权转换

- `/zen/v1/messages` 和 `/zen/go/v1/messages` 使用：

```http
x-api-key: <账号池中的 OpenCode API Key>
```

- Chat Completions、Responses、Models 和 Gemini 路由继续使用：

```http
Authorization: Bearer <账号池中的 OpenCode API Key>
```

- 转发前会删除客户端提交的两种鉴权头，本站访问令牌不会发送给 OpenCode。

## 修复

- 修复客户端通过 `x-api-key` 请求时返回 HTTP 401“访问令牌无效”。
- 修复 Messages 路由向 OpenCode 发送 Bearer 后返回 `AuthError: Missing API key`。
- 保持请求路径、查询参数、请求体和其他业务请求头不变。

## 请求示例

```bash
curl http://127.0.0.1:8787/zen/go/v1/messages \
  -H "x-api-key: gq_your_gateway_token" \
  -H "Content-Type: application/json" \
  -d '{"model":"qwen3.5-plus","max_tokens":256,"messages":[{"role":"user","content":"Hello"}]}'
```

## 升级步骤

1. 备份程序目录下的 `data/`。
2. 停止旧版本程序或 systemd 服务。
3. 使用对应平台的 v0.6.1 可执行文件替换旧文件。
4. 启动程序并重新发送 Messages 请求。
5. 使用 `--version` 确认版本。
